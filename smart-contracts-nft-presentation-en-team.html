Smart Contracts

A smart contract is code that enforces an agreement

A program stored on a blockchain that runs on IF → THEN logic: when the conditions are met, the agreement executes instantly — no intermediary, and no party can change it unilaterally.

Concept coined by Nick Szabo in 1994; made practical by the launch of Ethereum in 2015.

🥤

The classic analogy: a vending machine

  • Insert the exact amount
  • Select the product
  • The machine delivers it automatically
  • No clerk, no negotiation, no trust required

Under the hood

What does a smart contract look like?

A minimal escrow: the buyer deposits funds, which are released to the seller only after delivery is confirmed.

  • No trusted third party needed
  • Rules are public and readable by all
  • Execution is deterministic and auditable
// SPDX-License-Identifier: MIT pragma solidity ^0.8.24; contract Escrow { address public buyer; address payable public seller; bool public delivered; constructor(address payable _seller) payable { buyer = msg.sender; // buyer deposits funds seller = _seller; } function confirmDelivery() external { require(msg.sender == buyer, "Only buyer"); require(!delivered, "Already paid"); delivered = true; seller.transfer(address(this).balance); } }

From Finance to Code · 1/3

Options contracts in 60 seconds

📈 Call option

The right, not the obligation, to buy an asset at an agreed strike price. The buyer expects the price to rise.

Value = max(Market − Strike, 0)

📉 Put option

The right, not the obligation, to sell an asset at an agreed strike price. The buyer expects the price to fall.

Value = max(Strike − Market, 0)

Strike pricePrice at which the asset can be bought or sold
PremiumPrice the buyer pays the writer for the right
ExpirationDate the contract matures
Intrinsic + time valuePremium = intrinsic value + time (speculative) value
ITM · ATM · OTMIn-, at-, or out-of-the-money vs. the current price
European vs AmericanExercise only at expiry vs. any time until expiry

Source: lecture “Options Contracts” — Prof. El-Sayed El-Seify

From Finance to Code · 2/3

An option is already an IF → THEN contract

  • The writer locks collateral in the contract
  • The buyer pays the premium on-chain
  • An oracle reports the price at expiry
  • Payoff is settled automatically — no clearing house

Live examples of on-chain options protocols: Opyn, Derive (formerly Lyra), Hegic.

// Cash-settled European call (simplified) contract CallOption { address writer; address holder; uint strike; uint premium; uint expiry; IOracle oracle; // price feed function buy() external payable { require(msg.value == premium && holder == address(0)); holder = msg.sender; payable(writer).transfer(premium); } function settle() external { require(block.timestamp >= expiry, "Not expired"); uint spot = oracle.price(); // Vo = max(Vs - E, 0) uint payoff = spot > strike ? spot - strike : 0; payable(holder).transfer(payoff); payable(writer).transfer(address(this).balance); } }

Risks

“Code is law”… even when the code is wrong

Lesson from The DAO — 2016

A reentrancy bug let an attacker drain about 3.6M ETH (roughly a third of the fund), ultimately splitting the network into Ethereum and Ethereum Classic.

Code vulnerabilities

Oracle manipulation (bad external data)

Legal & regulatory ambiguity

Hard to fix after deployment

Mitigation: independent audits, testing, battle-tested libraries and bug-bounty programs.

Non-Fungible Tokens

What is an NFT?

A unique, non-interchangeable digital token, recorded on a blockchain by a smart contract, that proves ownership of a digital or physical asset — and its full transfer history.

Fungible

1
1
1
1

Every unit is identical and interchangeable: dollars, Bitcoin, ERC-20 tokens.

VS

Non-fungible

🎨
🎟
🏠
🎓

Each unit has its own identity: an artwork, a seat-specific ticket, a property deed, a diploma.

Anatomy of an NFT

What actually lives on-chain?

// on-chain (ERC-721) tokenId : 1337 owner : 0x4B2e…9aC1 tokenURI : "ipfs://bafy…/1337.json" royalty : 5% (EIP-2981) // off-chain metadata (IPFS) { "name": "Genesis #1337", "image": "ipfs://bafy…/1337.png", "attributes": [ { "trait_type": "Rarity", "value": "Legendary" } ] }

🔑 Unique tokenId

Ties the token to one specific contract and exactly one owner address.

🗂 Metadata

The image and traits usually live on IPFS or Arweave — not on the chain itself.

💸 Programmable royalties

A cut for the creator on every resale — standardized by EIP-2981, but enforcement depends on the marketplace.

Synergy

How they connect: an NFT is a smart contract

⚙️

Smart contract = the engine

Defines the rules for minting, ownership, transfer and royalties.

💎

NFT = the output

A unique token produced by the contract, representing one specific asset.

🔗

Together = programmable ownership

Assets that carry their rules with them wherever they go.

💡

Example: an NFT concert ticket that blocks resale above 110% of face value, sends 5% to the artist automatically, and turns into a digital collectible after the show — all in code.
